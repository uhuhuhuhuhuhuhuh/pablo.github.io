How IC2 and IC2C represent files

Public corpus reference: IC2C can point to an exact FastCDC chunk inside a public HTTP object. The share embeds the source URL and byte offset. The receiver requests that range and verifies the complete chunk SHA-256 before using it.

Recipe: zero, constant-byte, repeated-pattern and byte-counter regions are represented as deterministic instructions.

Reference: a repeated chunk can point backward to bytes already present in the same manifest.

Delta: ordinary IC2 can store a near-match to a previous chunk as a compact XOR or prefix/suffix patch.

Learned dictionary: useful samples from prior files are kept locally by file profile. The encoder may use those bytes as a Zstandard dictionary, but if the cumulative gain does not pay for embedding that dictionary, IC2 automatically falls back to the ordinary self-contained representation.

Literal: novel data is Zstandard-compressed when the pinned WASM codec is available, otherwise gzip is tried, and incompressible bytes remain raw.

IC2C is not self-contained: referenced public source URLs must remain accessible. Each referenced chunk and the complete reconstructed file are SHA-256 verified, so an unavailable or changed source causes an explicit failure rather than silent corruption. The public token remains capped at 1,500,000 characters.
