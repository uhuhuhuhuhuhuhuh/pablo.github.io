        Infinite Corridor extension
        
Generate very large virtual objects

        
Literal Babel paths become impractically huge for large files. A 1 TiB arbitrary object corresponds to roughly 717.5 billion two-character Corridor levels. XL mode therefore uses a compact deterministic ICXL1: recipe and streams the bytes directly from your browser to a file instead of building the whole object in memory.

        
Disk warning: non-zero XL modes write real data. A 1 TiB object can consume about 1 TiB of disk space and take a long time to write. The fast zero-filled option can create a logical-size file without streaming every zero byte, depending on browser and filesystem behavior.

Codec
Compatible with the original Babel mapping
The original project uses a 70-character alphabet and two characters per directory, so every level has 70² = 4,900 possible folders. The path is a bijective base-4,900 representation of a byte sequence represented in bijective base-256.
For exact search, Infinite Corridor converts your input bytes directly into that address. For browsing, it performs the inverse calculation and reconstructs the current directory's file. An empty file lives at the root.
Everything here executes as JavaScript in this browser tab. GitHub Pages only serves these static files. Selected files are read with the browser File API and are not uploaded by this application.
The Filename Regex tab searches filenames that you explicitly index from a local folder or imported catalog. It does not claim that arbitrary byte sequences have discoverable filenames.
XL mode is an Infinite Corridor extension for sizes where literal Babel paths are no longer practical. It uses compact deterministic recipes and streamed output; it is not a literal babel-usb directory path.
The original ESP32 project exposes the same core idea through MTP. Infinite Corridor independently reimplements the mathematical mapping for a browser interface and does not emulate USB or MTP.
