Codec
Compatible with the original Babel mapping
The original project uses a 70-character alphabet and two characters per directory, so every level has 70² = 4,900 possible folders. The path is a bijective base-4,900 representation of a byte sequence represented in bijective base-256.
For exact search, Infinite Corridor converts your input bytes directly into that address. For browsing, it performs the inverse calculation and reconstructs the current directory's file. An empty file lives at the root.
The Babel Discovery tab does not construct a PDF, PNG, archive, model, or document and then map it into Babel. Instead it deterministically traverses raw byte objects, tests the resulting bytes against the requested format and content conditions, and only returns naturally passing hits. Exact Babel paths are calculated from hit bytes on demand in a separate worker.
Babel's byte-to-path mapping does not contain arbitrary filename metadata. A filename regex is therefore used as a search label and expected extension, not as proof that a discovered object intrinsically has that filename. The result card states this explicitly.
Strict/content inspection materializes candidates up to 1 MiB each. For larger objects, raw virtual traversal remains possible when no structural/content claim is requested.
Because valid structured files are an extraordinarily tiny subset of all byte sequences, discovery-only searches can correctly return zero hits even after millions of attempts. The engine never inserts signatures, page text, pixels, archive entries, or tensor data to force a result.
Everything executes as JavaScript in this browser tab. GitHub Pages only serves these static files.
The original ESP32 project exposes the same core idea through MTP. Infinite Corridor independently reimplements the mathematical mapping for a browser interface and does not emulate USB or MTP.
